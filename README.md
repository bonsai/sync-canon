# sync-canon

Multi-device SQLite synchronization via GitHub. **User-created DBs only.**

## Two-Layer Architecture

sync-canon manages **two distinct layers** with separate access patterns:

```
┌────────────────────────────────────────────────────────┐
│  LAYER 1: DATA (.devices/)                             │
│  Business logic DBs — read/write, synced across WSLs   │
│  talk-db, .agents, wf-errors, .reposync...             │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│  LAYER 2: CHAT MEMORY (.memories/)                     │
│  Session fragments — read-only, mined from agent cache │
│  opencode, cagent, codex, cline...                     │
└────────────────────────────────────────────────────────┘
```

### LAYER 1: Data (.devices/)

User-designed DBs. **Read/write sync** between PC1-WSL ↔ PC2-WSL via GitHub.

| DB | Purpose | Size | Sync Priority |
|----|---------|------|---------------|
| `talk-db` | Content corpus (works, passages, relations) | 1.7MB | 🔴 High |
| `.agents` | Agent task triage | 2.6MB | 🟡 Medium |
| `wf-errors` | Workflow error tracking | 20KB | 🟢 Low |
| `.reposync` | Repo sync index | 52KB | 🟢 Low |
| `.bons/file-manager` | File manager index | 28KB | 🟢 Low |
| `ds-dashboard` | Analytics dashboard (regenerable) | 552KB | ⬜ Regen |

**Out of scope** (agent auto-generated cache, never sync):
- `.cline/`, `.opencode/`, `.codex/`, `.cursor/`, `.cagent/`
- `github-copilot/`, `JetBrains/`, `Docker/`, Browser profiles
- These live only on local machine, regenerated by agents

### LAYER 2: Chat Memory (.memories/)

**Read-only canonical** mined from agent session DBs. **Not synced as .db** — extracted as JSONL fragments.

| Source | DB Location | Access | Fragments |
|--------|-------------|--------|-----------|
| `opencode` | `~/.opencode/logs/conversations.db` | `messages.content` | 4 |
| `cagent` | `~/.cagent/session.db` (Windows) | `session_items.message_json` | 282 |
| `codex` | `~/.codex/history.jsonl` | JSONL directly | 0 |
| `cline` | `~/.cline/data/db/sessions.db` | TBD | — |

**Usage:**
- `extract_memories.py` → `.memories/<device>/`
- `ingest_memories.py` → `data/memory_ingest/` (talk-db compatible works + passages)
- `ripgrep`, `jq`, or talk-db FTS5 search

**Important:** Agent cache DBs themselves are **never committed** to sync-canon. Only the *mined fragments* (after heuristic filtering) become canonical.

## Principle

- **GitHub is the sync hub** for user-created canonical data
- **SQLite `.db` files are never committed** (binary, unmergeable)
- **Canonical = `schema.sql` + `table.jsonl`** (text, line-diffable, git-friendly)
- Each device exports its local DB to `.devices/<device>/`, pushes, and other devices pull + import

## True Topology: 5 Locations

```
┌─────────────────────────────────────────────────────────────┐
│                        GitHub Cloud                         │
│                    bonsai/sync-canon                        │
│              (schema.sql + *.jsonl only)                    │
└─────────────────────────────────────────────────────────────┘
         ↑↓ git push/pull              ↑↓ git push/pull
┌──────────────┐                  ┌──────────────┐
│  PC1 WSL     │                  │  PC2 WSL     │
│ ~/repos/     │                  │ ~/repos/     │
│ talk-db, etc │                  │ talk-db, etc │
└──────────────┘                  └──────────────┘
         ↑                                  ↑
   WSL mount                        WSL mount
┌──────────────┐                  ┌──────────────┐
│ PC1 Windows  │                  │ PC2 Windows  │
│ C:\Users\... │                  │ C:\Users\... │
│ agent cache  │                  │ agent cache  │
│ (NO sync)    │                  │ (NO sync)    │
└──────────────┘                  └──────────────┘
```

**Important**: PC1/PC2 Windows sides hold **only agent cache DBs** (auto-generated by Cline, OpenCode, Copilot, etc). These are **.scope-out**. They are local to each machine, disposable, and need no synchronization.

**Real sync happens only between WSL instances** (PC1 ↔ PC2) via GitHub canon.

## Workflow

### Layer 1: Data Export / Import

```bash
cd sync-canon

# Export (DB → canonical)
python scripts/export.py ~/repos/talk-db/db/talk.db wsl talk-db
python scripts/export.py ~/repos/wf-errors/wferr.db wsl wf-errors
python scripts/export.py ~/repos/.agents/data/triage.db wsl .agents

# Import (canonical → DB)
python scripts/import.py wsl talk-db ~/repos/talk-db/db/talk.db
python scripts/import.py wsl wf-errors ~/repos/wf-errors/wferr.db
python scripts/import.py wsl .agents ~/repos/.agents/data/triage.db

git add .devices/wsl/
git commit -m "sync(wsl): data layer export"
git push origin main
```

### Layer 2: Chat Memory Extract / Ingest

```bash
cd sync-canon

# Extract (agent session DBs → memory fragments)
python scripts/extract_memories.py wsl

# Ingest (fragments → talk-db compatible JSONL)
python scripts/ingest_memories.py wsl

# Results:
#   .memories/wsl/opencode.jsonl   (read-only canonical)
#   data/memory_ingest/works-wsl.jsonl
#   data/memory_ingest/passages-wsl.jsonl

git add .memories/wsl/  # if new fragments
```
